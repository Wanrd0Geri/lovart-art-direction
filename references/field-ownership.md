# Field Ownership

Every field has one owner. Do not repeat it in another layer for emphasis.

| Layer | Allowed | Forbidden |
| --- | --- | --- |
| Lovart interface recommendations | model, aspect ratio, resolution | world prose, batch logic, reference roles |
| Agent execution contract | deliverable count, independence, planning owner, grouping owner, metadata mode, research owner, batching, pause, retries, reconciliation | operative visual style prose |
| Shared visual capsule | medium behavior, cultural system, shape and spatial logic, material response, light structure, composition family | model name, aspect ratio, resolution, numbering, group names, workflow, sources, reports, negative checklist |
| Current item delta | current subject, function, state, environment, composition, one or two planned differences | global workflow, numbering rendered as text, unrelated alternatives |
| Variation constitution | fixed attributes, three or four independent axes, forbidden drift, quotas explicitly authorized by the user | a host-invented complete list when Lovart owns planning |
| Backend rejection checks | count failure, drift, structural failure, reference leakage, typography leakage, quality regression, retry action | positive visual prose sent to the image model |
| Continuity pack | current approved locks, actual used numbers, actual approved images, required re-uploads, allowed future variation | model, aspect ratio, resolution, future results, unresolved shorthand |

## Non-leakage rules

- Send only the shared visual capsule plus the current item delta to the image model.
- Keep names, numbers, group labels, source links, tables, batch state, and rejection prose in Lovart's execution layer.
- Do not put `Nano Banana Pro`, `Gemini`, numeric aspect ratios, or resolution labels in the prompt body or continuity pack.
- Camera and view rules may describe lens position, scale, crop behavior, depth, and composition, but not the interface aspect ratio.
- Engine names are optional supporting shorthand only after visible geometry, material, light transport, scale, and optical behavior are established. Do not stack engine, renderer, resolution, and generic quality tokens.

## Planning-owner consequences

### Host-specified

Show only the user-requested plan detail. A visible item table is allowed when the user needs to review it.

### Hybrid

Show only the user-confirmed high-cost items or quotas. Lovart completes the remaining contract internally.

### Agent-planned

Provide a concise constitution, authorized quotas, three or four variation axes, and forbidden drift.
Lovart creates the complete tracking contract internally.
Do not expose invented named regions, factions, subjects, or hundreds of item deltas.

## Compression limits

- Keep the shared visual capsule between 120 and 450 Chinese characters. Target 150-350.
- State each invariant once.
- Replace a negative with a positive target state when possible.
- Keep high-cost forbidden mechanisms in backend rejection checks, not in positive visual prose.
- Large output count does not justify a proportionally longer visible prompt.

## Continuity integrity

A continuity pack is a statement of current state, not a template for future state.
Reject unresolved language such as `同上次`, `保持原样`, `沿用之前`, `以上次为准`, `以最终报告为准`, or equivalent phrases.
Before generation begins, use `已用编号与名称：暂无` rather than referring to a future reconciliation report.
